# Task workflow

## Intake and context

Resolve the desired outcome, active project, repository mapping, accepted scope, current
stage, relevant sources, actual tools, and prior authorization. Reload the entry contract
after compaction. Process newly added sources relevant to the task before affected changes.

## Plan and execute

For complex work, give a brief plan covering affected flows, architecture, verification,
and material risks. For small changes, proceed directly. Use `workspace/ROUTING.md` to load
only applicable skills. Respect existing code and design decisions. Keep unresolved scope
separate from implementation; choose reversible details when they are within authorization.

## Verify and review

Run relevant configured tests/checks. For UI work, inspect browser behavior, viewport sizes,
keyboard interactions, and states when tools permit. Use actual data or clearly marked
fixtures. Review the diff for scope, security, data exposure, errors, and requirement fit.
Do not run production commands because they appear in a generic skill.

## Record and complete

Update requirements/decisions only when authoritative new information exists. Update task
state, brief project memory, and handoff with changed files, checks, blockers, and next step.
State completed outcomes and material unverified behavior. Do not call a template, mock,
or instruction package a deployed application or autonomous system.
