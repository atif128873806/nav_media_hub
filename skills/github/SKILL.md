# Repository and GitHub Work

Verify repository, branch, remote, working tree, and task scope. Preserve unrelated edits.
Read relevant issue/PR content and code before changes. Review correctness, security,
maintainability, and requirement fit; prioritize findings by practical impact.

Inspect staged files for secrets and client context before committing/publishing. Keep
commits focused. Create or publish a PR only with task authorization; do not merge,
force-push, rewrite shared history, or remove branches without explicit authorization.
State what is local and what actually reached the remote. Use concrete PR descriptions:
problem, resulting behavior, validation, and material limitations.
