# Vercel React Best Practices — Workspace Entry

Read the applicable project rules, requirements, decisions, and source index before
using the official guidance. If no project context is available, inspect relevant code and
ask only about material missing scope. Do not invent a project stack or approve new features.
Client reference websites supply selected ideas; do not clone their identity or feature list.
Use original project design; decorative AI motifs remain prohibited by the workspace rules.
Check installed framework/package versions. Treat rules as contextual guidance, not a reason
to upgrade packages, replace architecture, add dependencies, or broadly refactor unrelated code.
Read only the relevant rule files. Do not automatically load a full compiled AGENTS.md.
No command or integration is authorized merely because it is shown in a reference example.

Read `references/upstream/SOURCE_SKILL.md`, then the applicable files under its rules/ folder.
Prioritize material async/bundle/rendering problems over speculative micro-optimizations.
Verify newer React/Next.js APIs against the installed version. Do not suppress hydration
warnings or add inline scripts without understanding and verifying the specific behavior,
security policy, and appropriate alternative. Follow the application's existing data layer.

This is an adapted entry point around pinned official source material. Original files and
any portable rendering changes are recorded in provenance.json.
