# Professional Frontend UI/UX

Read project DESIGN.md, brand/assets, approved pages/flows, and reference roles. Inspect
existing UI before selecting an approach. When a reference is provided, read the workspace
reference policy: extract useful ideas and make an original design for this business.

Before implementing a new interface, write a short design direction: audience, primary
task, content density, hierarchy, typography, restrained color/tokens, layout, responsive
behavior, and why it suits the domain. Reuse established components rather than replacing
the design system. Build in the project's existing frontend stack; no Figma requirement.

Avoid decorative AI sparkles, robot/brain motifs, arbitrary purple/blue themes, meaningless
floating objects, gratuitous glass effects, generic oversized hero copy, excessive badges,
and putting every section in a rounded card. Functional icons are fine when consistent
and paired with accessible labels. Use original copy and authorized assets.

Use a coherent spacing/type scale and shared semantic color/component tokens. Give primary
and secondary actions distinct hierarchy. Use alignment, whitespace, grouping, and real
content to express importance. Keep animation purposeful and honor reduced motion.
Never invent metrics, testimonials, logos, or business claims to make a screen feel complete.

Design empty/loading/error/success/disabled states and long/absent content. Use semantic
HTML, visible focus, labels, understandable errors, keyboard access, sufficient contrast,
and responsive behavior from the actual content. Keep charts optional and explainable.

Inspect implemented screens in a browser when available: wide desktop, compact desktop,
and narrow mobile, plus content stress cases. Check interactions, alignment, overflow,
forms, dialogs, and console errors. If unavailable, report the limitation and perform
available build/code checks. See references/DESIGN_REVIEW.md for the final checklist.
